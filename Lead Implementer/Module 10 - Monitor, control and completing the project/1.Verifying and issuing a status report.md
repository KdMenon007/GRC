## Project Monitoring, Verification and Status Reporting

As the implementation project progresses, the **project manager must verify that reported progress reflects actual implementation**. It is not enough to rely only on what team members report.

The project manager should **trust the team but verify the actual results**.

### 1. Verify Actual Implementation

A team member may report that an activity has been completed, but the project manager should verify:

- Was the activity actually implemented?
    
- Is the new process being followed?
    
- Is the implemented control working?
    
- Is the expected result being achieved?
    
- Are employees using the new procedure correctly?
    

### Key Principle

> **Do not measure progress only on what is documented or reported. Verify what is actually happening.**

---

## 2. Implementation Checklists

Implementation checklists can be used as a form of **project quality control**.

They can help verify three areas:

### Design

Was the management system activity designed correctly?

### Implementation

Was the designed activity actually implemented?

### Effectiveness

Is the implemented activity producing the intended result?

---

### Example

For an ISO 27001 access-control procedure:

|Check|Verification|
|---|---|
|Design|Is the access-control procedure defined?|
|Implementation|Are access requests actually approved before provisioning?|
|Effectiveness|Are unauthorized or excessive permissions being identified and removed?|

---

## 3. Identify Implementation Gaps

Verification may reveal that:

- The design was not correctly implemented.
    
- Monitoring is insufficient.
    
- The procedure is impractical.
    
- The control is not producing the expected result.
    
- Employees are resisting the new practice.
    
- The original solution needs modification.
    
- An alternative solution is required.
    

The project manager should identify these issues early and take corrective action.

---

## 4. Use Checklists Periodically

Implementation checklists should be used periodically throughout the project rather than only at the end.

They provide an **accurate picture of the current project situation** and help identify problems before they become major issues.

---

# Project Status Reporting

The project manager should periodically prepare a **project status report**.

A status report summarizes the current condition of the project and helps management make:

- Decisions
    
- Corrective actions
    
- Resource decisions
    
- Priority decisions
    
- Project changes
    

Although information can be communicated verbally, a documented status report provides a reliable record.

---

## 5. What a Status Report Should Include

### Planned vs. Actual Progress

Compare:

- Planned activities
    
- Completed activities
    
- Delayed activities
    
- Remaining activities
    

Identify deviations from the original project plan.

---

### Schedule Status

Determine:

- Is the project progressing according to schedule?
    
- Are deadlines still achievable?
    
- Will the planned completion date be maintained?
    
- Does the project schedule need to change?
    

---

### Performance Status

Evaluate:

- Is the project under control?
    
- Are costs progressing as planned?
    
- Is time progressing as planned?
    
- Are intermediate results being achieved?
    
- Are deliverables meeting requirements?
    

---

## 6. Problems and Required Actions

The status report should identify:

- Current problems
    
- Unresolved issues
    
- Risks
    
- Required management actions
    
- Corrective actions
    
- Decisions required
    

The purpose is not simply to report problems but to determine **what needs to be done about them**.

---

## 7. Changes in Project Context

The project manager should monitor changes that could affect implementation.

Examples:

- Key employee leaves the organization.
    
- Responsibilities need to be reassigned.
    
- Organization structure changes.
    
- New legal requirements appear.
    
- Business priorities change.
    
- New customer requirements arise.
    
- New certification deadlines are introduced.
    

### Example

A critical team member leaves the organization.

The project manager may need to:

1. Identify the person's responsibilities.
    
2. Transfer responsibilities to other team members.
    
3. Check whether knowledge transfer is required.
    
4. Update the project plan.
    
5. Adjust the schedule if necessary.
    

---

## 8. Change Requests

Changes to the project are normal and should be **formally controlled**.

For example:

> Top management informs the project manager that certification is required earlier because an important customer contract depends on it.

The project manager may need to:

- Review the impact.
    
- Reprioritize activities.
    
- Allocate additional resources.
    
- Run some activities in parallel.
    
- Update the project schedule.
    
- Issue a change request.
    
- Obtain appropriate approval.
    

The current approved version of the **project plan should be updated** when changes are authorized.

---

## 9. Verify Deliverables on Site

Deliverables should not be considered complete merely because documents have been submitted.

The project manager should perform **implementation verification** where appropriate.

For example:

- Verify that an approved access-control procedure is actually followed.
    
- Check that security awareness training was conducted.
    
- Verify that controls are operating.
    
- Interview employees.
    
- Review evidence and records.
    
- Observe actual practices.
    

This confirms that the deliverable works in the real organization.

---

# Team Participation

The right people must participate in the implementation.

The project should involve people who understand the organization's **day-to-day operations**.

Important participants may include:

- Process owners
    
- Department managers
    
- IT/security personnel
    
- HR
    
- Procurement
    
- Legal/compliance
    
- Operational employees
    
- Other relevant stakeholders
    

### Important Principle

> **Do not implement a management system separately from the people and processes that actually run the organization.**

A management system that looks good on paper but bypasses daily operations is unlikely to be effective.

---

## Overall Monitoring Cycle

**Plan**  
↓  
**Execute**  
↓  
**Verify Actual Implementation**  
↓  
**Compare Planned vs. Actual**  
↓  
**Identify Deviations**  
↓  
**Take Corrective Action**  
↓  
**Update Project Plan**  
↓  
**Report Status**  
↓  
**Continue Monitoring**

### Key Takeaway

> **Effective project management requires more than tracking whether tasks are marked "completed." The project manager must verify implementation, evaluate effectiveness, monitor deviations, involve the right people, and take timely action when the project or its results are not progressing as planned.**
