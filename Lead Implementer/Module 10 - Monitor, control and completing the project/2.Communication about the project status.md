
## 1. Purpose of Project Status Communication

Project status communication is used to keep the **project team, project sponsor, and key stakeholders** informed about the progress of the implementation.

Effective communication helps to:

- Keep everyone aligned.
    
- Track project progress.
    
- Identify problems early.
    
- Support timely decision-making.
    
- Manage risks and resources.
    
- Avoid misunderstandings and conflicts.
    
- Maintain commitment to the project.
    

---

## 2. What Should Be Communicated?

Project status communication should provide information about:

- **Completed activities**
    
- **Activities still pending**
    
- **Reasons for delays or incomplete work**
    
- **Actions taken to address delays**
    
- **Unresolved problems**
    
- **Required decisions**
    
- **Upcoming activities**
    
- **Expected difficulties**
    
- **Project risks**
    
- **Resource requirements**
    
- **Changes in the project context**
    
- **Changes required to the project plan**
    

---

## 3. Status Report

A **project status report** is a documented representation of the current project situation.

It can compare:

> **Planned activities vs. Actual activities**

The report should identify significant deviations and indicate whether the original project schedule is still achievable.

### Example

|Area|Status|
|---|---|
|Policy development|Completed|
|Risk assessment|In progress|
|Awareness training|Delayed|
|Control implementation|On schedule|
|Internal audit|Upcoming|

---

## 4. Communicating Problems

Problems should not be hidden until the next major milestone.

Communicate:

- Current problems.
    
- Anticipated problems.
    
- Technical difficulties.
    
- Resource shortages.
    
- Delays.
    
- Conflicts.
    
- Issues requiring management intervention.
    

Early communication allows corrective action to be taken before the problem becomes more serious.

---

## 5. Communication With Key Stakeholders

Key stakeholders should receive **regular status updates**.

The frequency should be agreed with the **project sponsor**.

For example:

- Weekly — project team
    
- Biweekly — project manager and key stakeholders
    
- Monthly — project sponsor/top management
    
- Milestone-based — major project decisions
    

The exact frequency should depend on the size, complexity, and risk of the project.

---

## 6. Status Communication Before Meetings

A good practice is to send the **status report before the monitor and control meeting**.

This gives participants time to:

- Read the report.
    
- Understand the project situation.
    
- Identify concerns.
    
- Prepare questions.
    
- Think about required decisions.
    

Therefore, the meeting can focus on **discussion, decisions, and actions**, rather than simply presenting information.

---

## 7. Project Status Meeting

During the monitor and control meeting, the team should:

- Review the current status.
    
- Compare actual progress with the plan.
    
- Discuss deviations.
    
- Review unresolved issues.
    
- Discuss risks.
    
- Review resource requirements.
    
- Consider change requests.
    
- Make necessary decisions.
    
- Assign actions and responsibilities.
    

---

## 8. Communication After the Meeting

After the meeting, the project manager should communicate:

- Decisions made.
    
- Conclusions reached.
    
- Actions required.
    
- Person responsible for each action.
    
- Deadlines.
    
- Approved changes.
    
- Updated project information.
    

Meeting records should be maintained and distributed to the relevant project participants.

---

## 9. Communication Principles

Effective project status communication should be:

- **Clear** — everyone understands the situation.
    
- **Timely** — information is provided early enough to act.
    
- **Accurate** — based on actual project evidence.
    
- **Relevant** — provide information appropriate to each stakeholder.
    
- **Consistent** — use agreed reporting methods and frequency.
    
- **Action-oriented** — clearly identify what needs to happen next.
    

---

## 10. Key Questions

Project status communication should help management answer:

1. **Where are we now?**
    
2. **Are we following the project plan?**
    
3. **What has been completed?**
    
4. **What is delayed and why?**
    
5. **What problems remain unresolved?**
    
6. **What risks are emerging?**
    
7. **Are resources sufficient?**
    
8. **Are changes required?**
    
9. **What decisions are needed from management?**
    
10. **What happens next?**
    

---

### Quick Revision

**Project Status Communication**

**Collect status → Prepare report → Communicate → Review → Identify deviations → Make decisions → Assign actions → Follow up**

> **Effective communication maximizes understanding, creates confidence, and minimizes project risks.**
