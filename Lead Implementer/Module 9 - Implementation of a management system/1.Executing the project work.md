
Project execution is the **heart of the implementation project** and usually consumes most of the project time. The work is performed through **work assignments** and activities carried out between assignments.

### 1. Gathering and Analysing Data

The project team needs to gather and analyze relevant information about the organization.

For an ISO 27001 implementation, this could include:

- Existing policies and procedures
    
- Information security processes
    
- Assets and information
    
- Existing controls
    
- Legal and regulatory requirements
    
- Existing risks
    
- Current security practices
    

The purpose is to understand the **current situation** before deciding what needs to change.

---

### 2. Analysing Different Options

When an issue is identified, different solutions should be considered.

For example:

> A security weakness is identified. The team can evaluate several possible controls and determine which solution is most appropriate based on risk, cost, resources, and organizational requirements.

The most appropriate alternatives should then be shortlisted.

---

### 3. Recommending Solutions

The project team should recommend suitable solutions based on the existing situation.

A recommendation should include:

- Proposed solution
    
- Reason for the recommendation
    
- Implementation roadmap
    
- Required resources
    
- Expected outcomes
    
- Expected benefits
    

For ISO 27001, recommendations may relate to:

- Risk treatment
    
- Security controls
    
- Policies and procedures
    
- Access management
    
- Incident management
    
- Business continuity
    
- Employee awareness
    

---

### 4. Obtaining Decisions and Acceptance

Recommendations should be presented to the appropriate decision-makers.

For example:

1. Identify a security vulnerability.
    
2. Analyze possible solutions.
    
3. Recommend the most appropriate risk treatment.
    
4. Present the recommendation to top management or the relevant risk owner.
    
5. Obtain approval and acceptance.
    
6. Proceed with implementation.
    

This ensures that important decisions are **formally accepted before implementation**.

---

### 5. Executing Recommendations

After a solution is approved, it must be implemented.

Examples:

- Develop a new security policy.
    
- Implement a technical security control.
    
- Train employees.
    
- Change an existing process.
    
- Configure security systems.
    
- Implement risk treatment actions.
    

The Project Manager should follow up to ensure that approved recommendations are actually implemented.

---

### 6. Measuring Progress and Results

Implementation should not end with simply completing the assigned activity.

The project team should determine:

- Was the activity completed?
    
- Was it completed according to the plan?
    
- What changed as a result?
    
- Did the expected outcome occur?
    
- Are additional actions required?
    

For example:

> After implementing security awareness training, measure whether employee security awareness improved and whether security-related incidents decreased.

---

## 7. Project Manager's Responsibility

The Project Manager has their own work assignments, but has an **additional responsibility**: ensuring that the Project Team follows the agreed project plan.

The Project Manager should:

- Assign work.
    
- Track completion.
    
- Monitor deadlines.
    
- Check the quality of work.
    
- Follow up on delayed activities.
    
- Ensure recommendations are implemented.
    
- Monitor results.
    
- Escalate problems when necessary.
    
- Keep the project aligned with its objectives.
    

### Key Point

> **Project execution is not just completing tasks. It involves gathering information, analyzing options, recommending solutions, obtaining approval, implementing the decisions, and measuring the results.**
