
## Communication, Monitoring and Responsibility Allocation

### 1. Importance of Communication

Communication is a critical part of any implementation project.

The purpose is to communicate:

- Why the project is being implemented.
    
- What the project is expected to achieve.
    
- Why the project is important.
    
- How employees can participate.
    
- How employees can support the implementation.
    
- What is expected from the project team.
    

A project is a **temporary organization**, and communication acts as the **glue that holds the project together**.

Poor communication can lead to:

- Conflicts
    
- Delays
    
- Misunderstandings
    
- Missed activities
    
- Poor coordination
    
- Project slippage
    

---

## 2. Define a Communication Approach

Before starting the implementation, determine:

### Who needs to know?

Identify relevant stakeholders, such as:

- Top management
    
- Project sponsor
    
- Project team
    
- Department heads
    
- Employees
    
- External consultants
    
- Other interested parties
    

### What do they need to know?

Communicate information relevant to their responsibilities and involvement.

### How much do they need to know?

Not everyone needs the same level of information.

For example:

- **Top management:** Progress, risks, resources, major issues and decisions.
    
- **Project team:** Detailed tasks, deadlines and problems.
    
- **Employees:** Policies, responsibilities and expected changes.
    

### How often must they be informed?

Define an appropriate communication frequency.

---

## 3. Communication with the Project Team

Good communication is necessary for effective project monitoring and tracking.

The project manager should obtain prompt feedback about:

- Current progress of active tasks
    
- Problems encountered
    
- Expected problems
    
- Technical difficulties
    
- Delays
    
- Resource issues
    
- Activities that are waiting to start
    

This allows problems to be identified and addressed early.

---

## 4. Communication with Key Stakeholders

Key stakeholders should receive **regular project status reports**.

The reporting frequency should be agreed with the **project sponsor**.

A status report can include:

- What has been completed?
    
- What has not been completed?
    
- Why is work incomplete?
    
- What action has been taken?
    
- What problems remain unresolved?
    
- What action is required for unresolved problems?
    
- What difficulties are expected?
    
- What activities are waiting to be completed?
    

---

## 5. Benefits of Effective Communication

Effective communication:

- Maximizes understanding.
    
- Builds confidence.
    
- Improves coordination.
    
- Supports project monitoring.
    
- Enables faster problem resolution.
    
- Reduces misunderstandings.
    
- Minimizes project risks.
    
- Helps maintain project progress.
    

### Key Principle

> **Effective communication ensures that the right people receive the right information at the right time.**

---

# 6. Create an Implementation Calendar

Create a calendar showing:

- What needs to be done
    
- Who is responsible
    
- When it must be completed
    

Organize the project's major stages in **chronological order**.

---

## 7. Identify Dependencies

Determine which activities:

### Can be performed in parallel

Example:

- Policy development
    
- Asset inventory preparation
    

These may be performed simultaneously when resources allow.

### Must be completed first

Some activities depend on previous activities.

Example:

> Risk assessment → Risk treatment → Statement of Applicability → Risk Treatment Plan → Control implementation

Understanding dependencies prevents activities from being started prematurely.

---

## 8. Start Activities with Action Verbs

When documenting key project stages, start each activity with a **verb**.

Examples:

- **Define** the ISMS scope.
    
- **Conduct** gap analysis.
    
- **Identify** information security risks.
    
- **Assess** risks.
    
- **Select** risk treatment options.
    
- **Prepare** the Statement of Applicability.
    
- **Develop** policies.
    
- **Implement** controls.
    
- **Conduct** internal audit.
    
- **Perform** management review.
    
- **Prepare** for certification audit.
    

This makes responsibilities and expected actions clear.

---

## 9. Allocate Responsibilities

Every major stage of the project should have an **identified owner**.

The project team member responsible for a stage should be clearly identified.

For example:

|Project Activity|Responsible|
|---|---|
|Define ISMS scope|Project Manager|
|Conduct gap analysis|ISMS Team|
|Conduct risk assessment|Risk Owners / ISMS Team|
|Develop policies|CISO / ISMS Team|
|Implement technical controls|IT Team|
|Employee awareness|HR / CISO|
|Internal audit|Internal Auditor|
|Management review|Top Management|

Clear ownership ensures:

- Accountability
    
- Better coordination
    
- Easier progress tracking
    
- Faster escalation of problems
    
- Reduced risk of missed activities
    

---

### Key Principle

> **Communicate the purpose, responsibilities, progress, problems, and expectations throughout the project. Create a chronological implementation calendar, identify activity dependencies, and assign a clear owner to every major project stage.**
