## Operating the ISMS

**Operating the ISMS** means making sure the Information Security Management System works **continuously in the real organization**, not just during the ISO 27001 implementation or certification audit.

Think of it as:

> **Implement → Operate → Monitor → Review → Improve → Repeat**

### 1. Follow the ISMS policies and procedures

Employees and relevant teams must actually follow the documented security requirements.

For example:

- Access control procedures must actually be followed.
    
- Backups must actually run according to the backup policy.
    
- Security incidents must actually be reported and handled.
    
- User access must actually be reviewed.
    
- Vulnerability management procedures must actually be performed.
    
- Security awareness training must actually be conducted.
    

The organization should produce **real evidence** of these activities.

---

### 2. Operate the implemented controls

Controls selected during risk treatment must operate in day-to-day business.

For example, if MFA was selected to reduce the risk of unauthorized access:

**Plan:**

> Implement MFA for privileged accounts.

**Operate:**

> MFA is enabled and used whenever administrators log in.

**Evidence:**

> Identity-management configuration, authentication logs, access reviews, etc.

The objective is not simply to have the control documented but to ensure that it **actually reduces the risk**.

---

### 3. Maintain the ISMS documentation

The organization must ensure that policies, procedures, and other documented information remain **accurate and relevant**.

For example:

A company originally uses on-premises servers and has a procedure describing physical server access.

Later, the company moves its infrastructure to the cloud.

The organization should review the procedure because the original process may no longer reflect reality.

Therefore:

**Business/technology change → Review documentation → Update if necessary**

---

### 4. Manage changes

Changes to the organization can affect information security.

Examples:

- New software
    
- New applications
    
- Cloud migration
    
- New office
    
- New suppliers
    
- New business processes
    
- Organizational restructuring
    
- New types of information
    
- New regulations
    

These changes should be considered from an information-security perspective.

For example:

> A company introduces a new CRM system.

Before and during implementation, the organization should consider:

- Access control
    
- Data classification
    
- Encryption
    
- Backup
    
- Logging
    
- Privacy requirements
    
- Supplier security
    
- Business continuity
    

---

### 5. Assign document owners

Each important ISMS document should have an owner.

The owner is responsible for ensuring that the document remains:

- Accurate
    
- Relevant
    
- Approved
    
- Available to the appropriate people
    
- Consistent with actual practices
    

For example:

**Backup Policy → IT Manager**

**Information Security Policy → Top Management**

**Incident Response Procedure → CISO/Security Manager**

**HR Security Procedure → HR Manager**

---

### 6. Periodically review the documents

A common practice is to review important documents **at least annually** or whenever significant changes occur.

The review can result in:

**No change required**

or

**Document needs updating**

For example:

> Backup Policy reviewed on 10 August 2026 → Still applicable → No changes required.

The organization can retain evidence of the review.

---

### 7. Keep real records

Operating the ISMS generates records that demonstrate that activities actually happened.

Examples:

- Backup logs
    
- Security incident records
    
- Access-review records
    
- Training attendance
    
- Vulnerability scan reports
    
- Risk treatment status
    
- Audit reports
    
- Management review records
    
- Security monitoring records
    
- Change-management records
    

These records help demonstrate the **effectiveness and operation of the ISMS**.

---

### 8. Don't operate the ISMS only for the auditor

This is a very important principle.

Bad approach:

> "The audit is coming, so let's create the required records."

Good approach:

> "These are our normal security activities, and our records naturally demonstrate that we perform them."

The ISMS should become part of **normal business operations**, rather than a separate activity performed only for certification.

---

## Simple example

Suppose the ISMS requires:

> **Critical servers must be backed up every day.**

Operating the ISMS means:

1. Backup software is configured.
    
2. Daily backup jobs run.
    
3. Backup success/failure is monitored.
    
4. Failed backups are investigated.
    
5. Backup records are retained.
    
6. Restoration tests are performed periodically.
    
7. The backup procedure is reviewed when the infrastructure changes.
    
8. The control's effectiveness is eventually evaluated.
    

That's **operating the ISMS**.

### In one sentence

> **Operating the ISMS means continuously carrying out the policies, procedures, controls, risk treatments, monitoring activities, and other planned processes in day-to-day operations, while keeping them relevant and supported by genuine evidence.**

**Remember:**

**Implementing ISMS = Build it.**  
**Operating ISMS = Use it every day.**  
**Monitoring ISMS = Check whether it works.**  
**Improving ISMS = Make it better.**
