
These controls focus on **embedding information security into day-to-day IT operations**. The objective is to ensure that systems, endpoints, networks, applications, and infrastructure are operated securely and consistently.

### Key operational security areas

|Area|What should be implemented|
|---|---|
|**Endpoint security**|Protect laptops, smartphones, and other endpoint devices|
|**Privileged access**|Restrict and monitor administrator access|
|**Access control**|Give users only the access they need|
|**Privileged utilities**|Control powerful administrative tools|
|**Authentication**|Implement strong authentication such as MFA|
|**Capacity management**|Monitor resources and plan future capacity|
|**Malware protection**|Antivirus/EDR, application restrictions, web protection|
|**Backup**|Define backup frequency, technology, and testing|
|**Cryptography**|Define encryption requirements and key management|
|**Software installation**|Control what software can be installed and by whom|
|**Network security**|Protect, monitor, and restrict network communications|
|**Network services**|Define security requirements for network providers/services|
|**Network segregation**|Separate networks based on security requirements|
|**Time synchronization**|Synchronize systems to a trusted time source|
|**Redundancy**|Provide resilient/redundant systems|
|**Technical vulnerabilities**|Identify, prioritize, and remediate vulnerabilities|
|**Security testing**|Ensure testing does not negatively affect systems/data|
|**Logging & monitoring**|Record and review security-relevant events|

### Important examples

**Endpoint protection**

- Restrict unauthorized software installation.
    
- Encrypt devices.
    
- Deploy anti-malware/EDR.
    
- Control applications.
    

**Privileged access**

- Restrict administrator accounts.
    
- Apply least privilege.
    
- Monitor privileged activities.
    
- Control privileged utility programs.
    

**Authentication**

- Use strong authentication.
    
- Implement MFA where appropriate.
    
- Protect authentication credentials.
    

**Backup**  
Define:

> **What → How → How often → Where → How long → How to test recovery**

Backups should also be **tested**, because having a backup that cannot be restored does not provide effective protection.

**Cryptography**  
Define:

- Where encryption is required.
    
- Required protection level.
    
- Approved cryptographic mechanisms.
    
- Cryptographic key management.
    

**Network security**  
Implement:

- Firewalls
    
- Network monitoring
    
- IDS/IPS where appropriate
    
- Network access controls
    
- Authentication of network-connected systems
    
- Network segmentation
    

**Vulnerability management**

A practical process is:

**Discover → Scan → Assess severity → Prioritize → Remediate → Verify**

Critical vulnerabilities should receive higher priority based on their **risk and business impact**.

**Logging and monitoring**

Record relevant events such as:

- User activities
    
- Authentication events
    
- Administrative activities
    
- System errors
    
- Security events
    
- Network activity
    

Regular review of logs can help identify **suspicious behavior, vulnerabilities, and security incidents**.

### Disaster recovery / redundancy

Identify systems whose failure could significantly affect business operations and provide appropriate redundancy.

Examples:

- Additional servers
    
- Redundant network components
    
- Backup infrastructure
    
- Failover systems
    

The goal is to maintain availability when a primary component fails.

### Security during audit/testing

Security testing such as penetration testing should be planned so that it does not unnecessarily:

- Damage production systems
    
- Corrupt data
    
- Disrupt business operations
    
- Expose sensitive information
