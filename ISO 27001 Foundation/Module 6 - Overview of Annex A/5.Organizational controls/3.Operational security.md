
This group of controls focuses on organizing **day-to-day information security activities**. The objective is to ensure that regular security tasks are performed consistently according to defined rules and procedures.

### 1. Access Control Policy

The organization should establish an **Access Control Policy** defining rules for managing access.

The policy should define:

- Who approves access for employees.
    
- Who approves access for third parties.
    
- How access is provided.
    
- How user access is changed when an employee changes roles.
    
- How access is removed.
    

### 2. Access Provisioning

Access should be properly managed at the **technical level**.

The organization should define:

- Who is responsible for creating user accounts.
    
- How user rights are assigned.
    
- How access rights are modified when a user's role changes.
    
- How access is removed when it is no longer required.
    

**Example:**

When an employee moves from the HR department to IT:

> Existing HR access → Review → Remove unnecessary HR access → Provision required IT access.

### 3. User Identification

Users should be properly identified before providing access to systems or secure areas.

Examples:

- Unique username for application login.
    
- Biometric reader for entering a secure area.
    

The objective is to ensure that the organization can identify **who is accessing information or systems**.

### 4. Secure Authentication

The organization should define how users securely authenticate to their accounts.

Examples:

- Passwords
    
- Two-factor authentication (2FA)
    

Authentication mechanisms should be appropriate for the risks associated with the system or information.

### 5. Information Transfer

The organization should establish rules for securely transferring information to other organizations.

Examples:

- Protecting personal data transferred to a processor.
    
- Protecting information exchanged through email.
    
- Defining secure methods for transferring information.
    

### 6. Agreements with Third Parties

When information is exchanged with third parties, the organization should establish appropriate agreements.

These agreements should address the relevant security requirements for information exchange.

Supplier security and third-party security requirements are covered in more detail under the relevant supplier controls.

### 7. Operating Procedures for IT Systems

The organization should **document operating procedures for its IT systems**.

The organization can decide:

- How many procedures are required.
    
- How detailed the procedures should be.
    

However, the procedures should be documented so that security activities are performed consistently.

### Why Operating Procedures Are Important

Documented procedures help ensure that:

- Everyone understands the rules in the same way.
    
- Employees do not rely only on verbal instructions.
    
- Important security requirements are not forgotten.
    
- Different employees perform activities consistently.
    
- Security becomes part of normal IT operations rather than an afterthought.
    

### Key Point

The main objective is to ensure that **day-to-day IT and security activities are performed consistently, securely, and according to documented procedures**.

**Easy memory:**

**Access → Provision → Identify → Authenticate → Transfer → Agreements → Procedures**
