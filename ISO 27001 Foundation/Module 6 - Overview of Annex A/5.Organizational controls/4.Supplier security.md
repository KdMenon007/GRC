
Supplier security controls define requirements for **managing information security when working with suppliers, partners, and outsourced service providers**.

These controls are important because organizations increasingly **process and store information with third parties**, creating additional security risks.

### 1. Supplier Risk Assessment

The organization should assess the **information security risks associated with suppliers**.

Examples:

- Risk of data loss
    
- Risk of unauthorized access
    
- Risk of information disclosure
    
- Risks related to outsourced services
    

The identified supplier risks should drive the security requirements applied to the supplier.

### 2. Supplier Access

The organization should define:

- What systems suppliers can access.
    
- What information suppliers can access.
    
- What level of access they require.
    
- How supplier access is monitored.
    

Access should be based on the supplier's business requirements and associated risks.

### 3. Security Requirements for Suppliers

Suppliers that handle or process organizational information should be given appropriate **information security requirements**.

These requirements should address how the supplier must protect the organization's information.

### 4. Security Requirements in Supplier Contracts

Minimum information security requirements should be included in **supplier agreements/contracts**.

Examples:

- Who is authorized to access specific information.
    
- What information the supplier can access.
    
- How information must be protected.
    
- Security requirements for IT services.
    
- Required IT security safeguards.
    

Documenting requirements in contracts makes the security expectations clear to both parties.

### 5. IT Services and Security Safeguards

For suppliers providing IT services, the organization should specifically address the security risks associated with those services.

The supplier agreement can specify:

- Required security safeguards
    
- Security responsibilities
    
- Access requirements
    
- Protection requirements
    
- Service requirements
    

### 6. Monitoring Supplier Services

The organization should **monitor and review supplier services** to verify that the supplier continues to meet the agreed security requirements.

One way of monitoring supplier services is through **regular service reports**.

**Example:**

If an agreement with an Internet Service Provider requires **99.98% availability per month**, the organization can review the supplier's monthly service report to verify whether the agreed availability level was achieved.

### 7. Cloud Services — A.5.23

**A.5.23 Information Security for Use of Cloud Services** is a **new control introduced in ISO 27001:2022** that was not present in the 2013 version.

It requires the organization to establish a process for:

- Acquiring cloud services from third parties.
    
- Managing cloud services.
    
- Addressing information security requirements related to cloud services.
    

Cloud services can therefore be considered within the broader context of **supplier security** because they are provided by third parties.

### Key Point

Supplier security ensures that information remains protected **even when processing, storage, IT services, or other activities are outsourced to third parties**.

**Easy memory:**

**Assess Supplier Risk → Define Access → Set Security Requirements → Put Requirements in Contracts → Monitor Supplier → Manage Cloud Services**
