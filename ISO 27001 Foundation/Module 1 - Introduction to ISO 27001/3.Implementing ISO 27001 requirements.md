
## Overview of PDCA in ISO 27001

ISO/IEC 27001:2022 follows the **PDCA (Plan-Do-Check-Act)** cycle to establish, operate, monitor, and continuously improve an **Information Security Management System (ISMS).**

The PDCA model ensures that information security is not a one-time implementation activity but a **continuous improvement process**.

The cycle ensures organizations:

- Understand their business environment
    
- Identify and manage security risks
    
- Implement appropriate controls
    
- Measure security effectiveness
    
- Improve security processes continuously
    

---

# ISO 27001 PDCA Cycle

```
                 PLAN
                  |
        Establish ISMS Requirements
                  |
                  ↓
DO  → Implement Controls → CHECK
                  ↑
                  |
                 ACT
                  |
        Continual Improvement
```

PLAN  → Decide what to do
        (Risk assessment, controls, SoA)

DO    → Do what was planned
        (Implement controls)

CHECK → Verify it works
        (Monitoring, audits, reviews)

ACT   → Make it better
        (Corrective actions, improvements)
        
---

# Relationship Between PDCA and ISO 27001 Clauses

|PDCA Phase|ISO 27001 Clauses|Main Purpose|
|---|---|---|
|Plan|Clauses 4–7|Establish ISMS foundation|
|Do|Clause 8|Implement and operate ISMS|
|Check|Clause 9|Monitor and evaluate effectiveness|
|Act|Clause 10|Improve ISMS continuously|

---

# 1. PLAN Phase (Clauses 4–7)

## Purpose

The Plan phase establishes the foundation of the ISMS.

During this phase, the organization defines:

- What needs to be protected
    
- Why protection is required
    
- What risks exist
    
- Which controls are required
    
- How security will be managed
    

The Plan phase answers:

> "What are we protecting, what are the risks, and how will we manage them?"

---

# 2. DO Phase (Clause 8)

## Purpose

The Do phase implements the plans created during the Plan phase.

The organization executes:

- Risk treatment plans
    
- Security controls
    
- Operational security processes
    

The Do phase answers:

> "How do we implement security controls in daily operations?"

---

# 3. CHECK Phase (Clause 9)

## Purpose

The Check phase evaluates whether the ISMS is working effectively.

The organization measures:

- Security performance
    
- Control effectiveness
    
- Risk status
    
- Compliance level
    

The Check phase answers:

> "Are our security controls working as expected?"

---

# 4. ACT Phase (Clause 10)

## Purpose

The Act phase ensures continuous improvement of the ISMS.

The organization:

- Fixes problems
    
- Implements corrective actions
    
- Improves security processes
    

The Act phase answers:

> "How can we make security better?"

# Complete ISO 27001 PDCA Lifecycle Example

## Scenario: Ransomware Risk

### PLAN

Identify:

- Critical servers
    
- Ransomware threat
    
- Business impact
    

Risk:

High

Plan controls:

- EDR
    
- Backup
    
- User training
    

---

### DO

Implement:

- EDR deployment
    
- Backup solution
    
- Security awareness training
    
- SOC monitoring
    

---

### CHECK

Measure:

- Malware detection rate
    
- Backup success rate
    
- Incident response time
    

Audit:

Verify controls are working.

---

### ACT

Improve:

- Update incident response plan
    
- Improve detection rules
    
- Conduct additional training

# Final Interview Summary

**ISO 27001 follows the PDCA cycle:**

### PLAN (Clauses 4–7)

Understand organization, define scope, establish policy, identify risks, and plan controls.

### DO (Clause 8)

Implement risk treatment plans and operate security controls.

### CHECK (Clause 9)

Monitor performance, conduct audits, and review ISMS effectiveness.

### ACT (Clause 10)

Fix issues, apply corrective actions, and continuously improve the ISMS.

**In simple terms:**

> ISO 27001 uses PDCA to ensure organizations identify security risks, implement controls, measure effectiveness, and continuously improve their information security posture.
